# QueueSense — Complete Code Explanation

This document explains every file in the QueueSense project that is part of the source tree. It identifies the programming language, what each file contains, whether it is active QueueSense code or scaffold/support code, and how it contributes to the required output.

## 0. Project execution model

QueueSense is a full-stack TypeScript web application:

```text
Browser
  ├─ React/Vite frontend
  │    ├─ pages and components
  │    ├─ browser camera + TensorFlow.js/COCO-SSD
  │    └─ local demo persistence and BroadcastChannel sync
  │
  └─ tRPC client at /api/trpc
          │
          ▼
Express server
  ├─ authentication/OAuth
  ├─ typed QueueSense API procedures
  ├─ database helpers through Drizzle ORM
  └─ storage/notification/runtime adapters
          │
          ▼
MySQL relational database
  ├─ users
  ├─ services
  ├─ counters
  ├─ queueEntries
  ├─ queueEvents
  ├─ cameraStations
  └─ queueMetrics
```

There are two persistence paths:

1. **Relational backend path:** the server uses Drizzle ORM and MySQL through `DATABASE_URL`. Queue API procedures can persist queue entries, events, and camera metrics.
2. **Hackathon fallback path:** the browser uses `localStorage` and `BroadcastChannel` so the demo works even when database records are not seeded. The UI still queries the backend status procedure and displays whether it is using the relational database or the fallback.

The project uses **TypeScript** for frontend and backend code, **CSS** for visual styling, **HTML** for the document shell, **SQL** for the relational schema/migrations, **JSON** for configuration/metadata, **Markdown** for documentation, and a small **JavaScript** runtime debug collector.

# 1. Root-level files

## `.gitignore`

- **Language:** Git ignore syntax.
- **Contains:** Paths Git should not track, such as installed dependencies, environment files, generated output, logs, and temporary files.
- **Why it matters:** Prevents secrets, `node_modules`, compiled `dist` files, and runtime logs from entering the repository.

## `.gitkeep`

- **Language:** Empty marker file.
- **Contains:** No application logic.
- **Why it exists:** Git does not track empty directories; this file preserves the project root or an otherwise empty directory in version control.

## `.prettierignore`

- **Language:** Prettier ignore syntax.
- **Contains:** Files/directories that should not be reformatted.
- **Output/change:** Keeps generated files, migrations, and framework-owned files from being rewritten by `pnpm format`.

## `.prettierrc`

- **Language:** JSON configuration.
- **Contains:** Formatting preferences used by Prettier.
- **Output/change:** Makes code formatting consistent across TypeScript, TSX, JSON, Markdown, and other supported files.

## `.project-config.json`

- **Language:** JSON.
- **Contains:** WebDev project metadata, project identity, and scaffold configuration.
- **Output/change:** Lets the managed WebDev environment know how to run, preview, and maintain QueueSense.

## `README.md`

- **Language:** Markdown.
- **Contains:** The main project explanation: problem, solution, features, architecture, stack, code layers, API contract, data relationships, setup commands, Supabase/MySQL setup, camera design, user workflows, demo script, testing checklist, limitations, future improvements, and Git workflow.
- **Output/change:** Gives developers and judges the instructions needed to understand, run, test, and present QueueSense.

## `components.json`

- **Language:** JSON.
- **Contains:** shadcn-style UI component configuration, including aliases and styling conventions.
- **Output/change:** Lets UI component tooling generate/import reusable components consistently.

## `drizzle.config.ts`

- **Language:** TypeScript.
- **Contains:** Drizzle Kit configuration. It reads `DATABASE_URL`, uses `drizzle/schema.ts`, generates into `drizzle/`, and declares MySQL as the dialect.
- **Output/change:** Powers `pnpm drizzle-kit generate` and `pnpm db:push`; the generated SQL is based on `drizzle/schema.ts`.

## `package.json`

- **Language:** JSON.
- **Contains:** Project name, scripts, runtime dependencies, development dependencies, and package-manager settings.
- **Important scripts:**
  - `pnpm dev`: starts the TypeScript/Express server with Vite development mode.
  - `pnpm build`: builds the React frontend and bundles the Express server.
  - `pnpm start`: starts the production server bundle.
  - `pnpm check`: runs strict TypeScript checking.
  - `pnpm test`: runs Vitest.
  - `pnpm db:push`: generates and applies Drizzle migrations.
- **Important dependencies:** React, Vite, TypeScript, Wouter, tRPC, React Query, Drizzle, MySQL, Express, Lucide, Sonner, TensorFlow.js/COCO-SSD via HTML CDN scripts, and Vitest.

## `pnpm-lock.yaml`

- **Language:** YAML-like package-lock format generated by pnpm.
- **Contains:** Exact resolved versions and dependency graph.
- **Output/change:** Ensures installs are repeatable across machines and CI environments.

## `template.json`

- **Language:** JSON.
- **Contains:** WebDev scaffold/template metadata and default project configuration.
- **Output/change:** Describes how the full-stack project is initialized and managed by the platform.

## `tsconfig.json`

- **Language:** JSON.
- **Contains:** Strict TypeScript compiler settings, source inclusion, aliases (`@/*` and `@shared/*`), DOM libraries, and no-output compilation.
- **Output/change:** Makes type errors visible before build and allows imports such as `@/lib/demoStore`.

## `vite.config.ts`

- **Language:** TypeScript.
- **Contains:** Vite plugins for React, Tailwind, JSX source locations, Manus runtime integration, and browser debug collection. It also defines aliases, project root, public directory, build output, and allowed development hosts.

## `vite.config.ts.bak`

- **Language:** TypeScript backup configuration.
- **Contains:** Earlier Vite configuration retained by the scaffold.
- **Output/change:** Not used by the active build unless manually restored; useful as a rollback/reference file.

## `vitest.config.ts`

- **Language:** TypeScript.
- **Contains:** Vitest root, aliases, Node test environment, and test globs for both `server/**/*.test.ts` and `client/src/**/*.test.ts`.

# 7. Frontend domain state and tests

## `client/src/lib/demoStore.ts`

- **Language:** TypeScript/TSX-compatible TypeScript.
- **Contains:**
  - `QueueStatus`, `Service`, `QueueEntry`, `QueueStats`, and `QueueState` types.
  - Seed services: Admissions, Accounts, Library, and Certificates.
  - Seed entries such as `A014` serving and `A018` as the demo student.
  - `localStorage` persistence under `queuesense-demo-state-v1`.
  - `BroadcastChannel` and storage-event synchronization under `queuesense-demo-sync-v1`.
  - `useQueueStore()` actions: join, cancel, call next, start serving, complete, skip, pause/resume, physical-count update, and reset.
  - Derived selectors for active token, waiting entries, service summaries, and estimated wait.
  - `getPeopleAhead`, `getTokenWait`, and `getStats` calculations.
- **Output/change:** This is the browser fallback data layer. It makes all dashboard screens react to one shared state, persists changes across refreshes, and synchronizes other tabs/devices using browser messaging.

### Important state rules

- `WAITING → CALLED → SERVING → COMPLETED` is the normal path.
- `WAITING → CANCELLED` is a student exit.
- `CALLED/SERVING → SKIPPED` is a staff exit.
- A second active token cannot be called while another token is `CALLED` or `SERVING`.
- Physical count and digital token positions remain separate.

## `client/src/lib/queueLogic.test.ts`

- **Language:** TypeScript test code.
- **Contains:** Vitest tests for people-ahead calculation, approximate digital wait, and exclusion of cancelled entries.
- **Output/change:** Proves that the domain calculations produce the expected `3 people ahead` and `9 minute` output for `A018` in the demo state.

# 9. Backend entry points and API

## `server/routers.ts`

- **Language:** TypeScript.
- **Contains:** The typed application router:
  - `system.health` and `system.notifyOwner` from `systemRouter`.
  - `auth.me` and `auth.logout`.
  - `queue.status`: reports `tRPC over /api/trpc`, relational database/demo fallback mode, and realtime mode.
  - `queue.join`: validates numeric service/counter/user IDs and creates a persistent token.
  - `queue.event`: validates and records `JOINED`, `CALLED`, `SERVING`, `COMPLETED`, `SKIPPED`, or `CANCELLED` events.
  - `queue.metric`: validates and stores aggregate camera metrics.
- **Output/change:** This file is the backend API contract. tRPC exposes it under `/api/trpc`, and `client/src/lib/trpc.ts` turns it into typed React hooks.

## `server/queueDb.ts`

- **Language:** TypeScript.
- **Contains:** Database-facing queue functions:
  - `getQueueBackendStatus()` checks whether Drizzle has a database connection.
  - `createPersistentQueueEntry()` finds the next sequence number, creates a token, inserts `queueEntries`, and inserts a `JOINED` event.
  - `recordPersistentQueueEvent()` appends auditable status history.
  - `recordPersistentQueueMetric()` stores aggregate people count and estimated wait.
  - `getLatestPersistentMetric()` retrieves the most recent camera metric.
- **Output/change:** Converts API requests into relational database reads/writes. If no database is configured, it returns a `persisted: false` result so the browser demo remains available.

## `server/db.ts`

- **Language:** TypeScript.
- **Contains:** Lazy Drizzle/MySQL connection, `upsertUser`, and `getUserByOpenId`.
- **Output/change:** Creates the database client only when `DATABASE_URL` exists, persists authenticated users, and avoids crashing local tooling when a database is unavailable.

## `server/routers.ts` input validation

- **Technology:** Zod through tRPC.
- **Output/change:** Rejects invalid IDs, negative counts, negative wait times, and invalid event types before any database write occurs.

## `server/queue.api.test.ts`

- **Language:** TypeScript with Vitest.
- **Contains:** API tests for `queue.status` response shape and invalid camera metric rejection.
- **Output/change:** Confirms the backend contract exists and validates bad input before persistence.

## `server/auth.logout.test.ts`

- **Language:** TypeScript with Vitest.
- **Contains:** Test for clearing the session cookie with secure, HTTP-only, same-site options.
- **Output/change:** Verifies authentication logout behavior.

## `server/storage.ts`

- **Language:** TypeScript.
- **Contains:** `storagePut`, `storageGet`, and `storageGetSignedUrl` helpers using the Manus Forge storage service and S3 presigned URLs.
- **Output/change:** Supports safe file upload/download without storing binary bytes directly in MySQL. QueueSense does not currently store camera video.

These are mostly WebDev scaffold infrastructure. They are active at runtime even when a specific QueueSense screen does not call them directly.

## `server/_core/index.ts`

- **Language:** TypeScript.
- **Contains:** Express app creation, JSON/form body parsing, storage proxy registration, OAuth route registration, tRPC middleware at `/api/trpc`, Vite development mounting, production static serving, port discovery, and server startup.
- **Output/change:** Starts the actual backend/frontend server and mounts all HTTP entry points.

## `server/_core/context.ts`

- **Language:** TypeScript.
- **Contains:** tRPC request context with `req`, `res`, and optional authenticated `user` resolved through the SDK.
- **Output/change:** Every tRPC procedure receives a consistent request context.

## `server/_core/trpc.ts`

- **Language:** TypeScript.
- **Contains:** tRPC initialization with SuperJSON, `publicProcedure`, `protectedProcedure`, and `adminProcedure` middleware.
- **Output/change:** Enforces authentication and admin authorization for procedures that use those procedure types.

## `server/_core/env.ts`

- **Language:** TypeScript.
- **Contains:** Centralized environment variable object: app ID, JWT secret, database URL, OAuth URL, owner ID, production flag, Forge API URL/key.
- **Output/change:** Keeps secrets/configuration out of business logic and source literals.

## `server/_core/cookies.ts`

- **Language:** TypeScript.
- **Contains:** Session-cookie option construction for secure/HTTP-only/same-site behavior.
- **Output/change:** Ensures authentication cookies are configured consistently for login and logout.

## `server/_core/oauth.ts`

- **Language:** TypeScript.
- **Contains:** `/api/oauth/callback`, OAuth state/nonce verification, code exchange, user-info retrieval, user upsert, session-token creation, and secure session cookie creation.
- **Output/change:** Turns an OAuth callback into an authenticated QueueSense session.

## `server/_core/sdk.ts`

- **Language:** TypeScript.
- **Contains:** Server SDK client for authenticating incoming requests, exchanging OAuth codes, retrieving user information, and creating session tokens.
- **Output/change:** Encapsulates communication with the Manus authentication backend.

## `server/_core/systemRouter.ts`

- **Language:** TypeScript.
- **Contains:** Public health procedure and admin-only owner notification procedure.
- **Output/change:** Provides generic system health and platform notification APIs.

## `server/_core/notification.ts`

- **Language:** TypeScript.
- **Contains:** Notification payload validation, length limits, endpoint construction, authenticated POST to the Manus Notification Service, and graceful failure handling.
- **Output/change:** Sends safe owner notifications when an authorized procedure requests one.

## `server/_core/storageProxy.ts`

- **Language:** TypeScript.
- **Contains:** `/manus-storage/*` Express route that requests a signed URL and redirects the browser to storage.
- **Output/change:** Provides secure downloads while keeping storage credentials server-side.

## `server/_core/dataApi.ts`

- **Language:** TypeScript.
- **Contains:** Scaffold wrapper for the built-in data API.
- **Output/change:** Makes future server-side built-in data operations available without exposing credentials to the browser.

## `server/_core/heartbeat.ts`

- **Language:** TypeScript.
- **Contains:** Scaffold heartbeat/runtime support.
- **Output/change:** Supports platform lifecycle/heartbeat behavior; it is not part of queue calculations.

## `server/_core/imageGeneration.ts`

- **Language:** TypeScript.
- **Contains:** Built-in image generation service wrapper.
- **Output/change:** Enables future server-side generated visual assets; QueueSense does not require it for camera detection.

## `server/_core/llm.ts`

- **Language:** TypeScript.
- **Contains:** Built-in LLM service wrapper.
- **Output/change:** Supports future AI assistance features; queue counting uses COCO-SSD instead of an LLM.

## `server/_core/map.ts`

- **Language:** TypeScript.
- **Contains:** Map proxy/configuration helper.
- **Output/change:** Supports future campus/counter maps.

## `server/_core/vite.ts`

- **Language:** TypeScript.

## `server/_core/voiceTranscription.ts`

- **Language:** TypeScript.

# 11. Database schema and migrations

## `drizzle/schema.ts`

- **Language:** TypeScript.
- **Contains:** Relational table definitions and inferred types:
  - `users`: authenticated people and roles.
  - `services`: destination name, token prefix, average service time, active flag.
  - `counters`: service assignment, status, staff assignment.
  - `queueEntries`: token, sequence number, state, timestamps, foreign keys.
  - `queueEvents`: append-only queue transition history.
  - `cameraStations`: counter mapping and JSON ROI configuration.
  - `queueMetrics`: aggregate people count and estimated wait.
- **Output/change:** This is the source of truth for Drizzle migrations and backend database types. Foreign keys and indexes enforce relationships and speed up active-queue queries.

## `drizzle/0000_dry_warbound.sql`

- **Language:** MySQL SQL.
- **Contains:** Original scaffold migration, including the `users` table.
- **Output/change:** Creates the authentication/user persistence table.

## `drizzle/0001_clear_nehzno.sql`

- **Language:** MySQL SQL.
- **Contains:** Generated migration for the QueueSense tables, foreign keys, unique constraints, and indexes.
- **Output/change:** Creates the relational database layer required by queue persistence.

## `drizzle/meta/0000_snapshot.json`

- **Language:** JSON.
- **Contains:** Drizzle’s snapshot of the original schema.
- **Output/change:** Lets Drizzle compare the previous schema to later schema versions.

## `drizzle/meta/0001_snapshot.json`

- **Language:** JSON.
- **Contains:** Snapshot of the schema after services/counters/entries/events/stations/metrics were added.
- **Output/change:** Supports future migration diffs.

## `drizzle/meta/_journal.json`

- **Language:** JSON.
- **Contains:** Ordered migration journal with migration tags and timestamps.
- **Output/change:** Records migration order so Drizzle knows which migrations have been generated/applied.

## `drizzle/relations.ts`

- **Language:** TypeScript.
- **Contains:** Currently an empty relations scaffold.
- **Output/change:** It is a future extension point for Drizzle relation helpers; the actual foreign keys are already declared in `schema.ts`.

## `drizzle/migrations/.gitkeep`

- **Language:** Empty marker file.
- **Output/change:** Preserves the migration directory in Git.

# 14. How the required output is produced

## Landing page output

1. Browser loads `client/index.html`.
2. `client/src/main.tsx` mounts React.
3. `App.tsx` matches `/` to `Landing.tsx`.
4. `Landing.tsx` uses `PublicHeader` and CSS classes from `index.css`.
5. The browser displays the product story and links to the student workflow.

## Student token output

1. `StudentDashboard.tsx` calls `useQueueStore()`.
2. `demoStore.ts` loads the persisted state or seed state.
3. Service cards derive physical queue count and estimated wait.
4. `joinQueue()` creates/reuses a token, such as `A018`.
5. The selected entry is passed to `getPeopleAhead()` and `getTokenWait()`.
6. The UI renders current token `A014`, people ahead `3`, and wait `~9 min`.
7. The backend API contract is available through `queue.join`; the local path remains the safe demo fallback.

## Staff transition output

1. `StaffDashboard.tsx` finds the active entry for the selected service.
2. A button calls an action from `demoStore.ts`.
3. The action checks the current status before changing it.
4. `writeState()` persists and broadcasts the new state.
5. Other tabs receive the state and re-render automatically.
6. Stats and activity lists derive from the updated entries.

## Camera output

1. `CameraStation.tsx` starts in deterministic demo mode.
2. The canvas draws the ROI and simulated person boxes.
3. **Use webcam** calls `getUserMedia()`.
4. COCO-SSD detects objects in the video.
5. Only detections with `class === "person"` are kept.
6. Bounding-box centers are tested against the ROI.
7. The rolling median stabilizes the count.
8. The UI displays raw detections, filtered people, and approximate wait.
9. Only aggregate values are eligible for persistence; video is not stored.

## Backend API output

1. `main.tsx` creates the tRPC HTTP batch client at `/api/trpc`.
2. `AppShell` invokes `trpc.queue.status.useQuery()`.
3. Express in `server/_core/index.ts` receives the request.
4. tRPC resolves `appRouter.queue.status` in `server/routers.ts`.
5. `queueDb.ts` calls `getDb()` from `server/db.ts`.
6. The response reports relational database mode or demo fallback.
7. The top bar displays the persistence/API state.

## Relational database output

1. `drizzle/schema.ts` defines tables/types.
2. `drizzle-kit generate` creates `drizzle/0001_clear_nehzno.sql`.
3. The migration creates tables, indexes, constraints, and foreign keys.
4. `queueDb.ts` inserts queue entries/events/metrics through Drizzle.
5. MySQL persists the records beyond browser refreshes and server restarts.
6. The browser demo can continue operating locally if the database has no seeded queue records.

# 15. Files that are generated or excluded from this explanation

The inventory intentionally excludes:

- `node_modules/`: installed third-party packages; not project-owned source.
- `dist/`: generated production frontend/server output.
- `.git/`: Git object database and history.
- `.manus-logs/`: runtime logs generated by the managed environment.
- Incremental compiler/cache files: generated by TypeScript/tooling.

Those files are not omitted accidentally; they are generated/vendor artifacts rather than QueueSense source subdivisions.
